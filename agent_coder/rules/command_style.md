# Единый командный стиль

Применяй эти правила ко всем операциям и workspace независимо от наличия
`AGENTS.md`. Проектные инструкции могут уточнять workflow, но не отменять его
адаптивность.

## Адаптивное исследование проекта

1. Сначала определи задачу и её scope. Если пользователь указал конкретный файл
   или узкую правку, не делай полный обзор репозитория.
2. Если scope неясен или задаче нужно понимание проекта, начни с краткого обзора
   структуры: корень проекта, основные каталоги и подходящие точки входа. Не
   выводи полное дерево и не читай все файлы подряд.
3. Найди инструкции и документацию, относящиеся к задаче: например, `AGENTS.md`,
   README и профильные Markdown-документы. Читай их выборочно; не считай, что все
   документы одинаково важны.
4. Затем найди нужные символы и файлы; изучай только относящиеся к задаче участки
   кода.
5. Группируй независимые безопасные поиски и чтения в один пакетный вызов.
   Зависимые действия выполняй последовательно. Соблюдай exit code, разрешения и
   подтверждения инструментов.
6. После изменений выбери проверки по scope; перед публикацией соблюдай полный
   CI gate проекта.

Не превращай этот порядок в обязательный полный аудит для маленькой точечной
задачи. Не требуй читать все Markdown-файлы или сначала обходить весь репозиторий.

## Выполнение команд

- Перед командами собери минимально необходимый контекст.
- Группируй независимые read-only команды в один пакетный вызов; зависимые
  команды выполняй последовательно.
- Для каждой важной команды сохраняй и проверяй её exit code отдельно.
- Не теряй ошибки за pipe: учитывай статус исходной команды, а не только
  последнего этапа конвейера.
- Сначала сохрани статус команды, затем при необходимости ограничивай вывод.
- Не объединяй команды для обхода разрешений инструментов, подтверждений или
  проверок безопасности; соблюдай ограничения и последовательность одобрения.
