# AGENTS.md — правила проекта agent-coder

Общий стандарт Python-проектов описан в
`agent_coder/rules/project_standard.md`. Важно: когда в workspace есть
`AGENTS.md`, встроенный стандарт автоматически в system prompt не добавляется.
Этот файл задаёт правила именно для agent-coder и имеет приоритет для проекта.
Если задача зависит от требований общего стандарта, прочитай соответствующие
разделы `project_standard.md`, не предполагая, что они уже есть в контексте.

## Единое ядро: CLI и Telegram — тонкие адаптеры

Вся логика агента живёт **только** в `agent_coder/agent/`,
`agent_coder/llm/`, `agent_coder/tools/`. CLI (`__main__.py`) и Telegram
(`telegram/`) — адаптеры: парсинг ввода, рендер вывода, транспорт. Никакой
бизнес-логики в адаптерах.

**Почему:** A10 (сессия 2026-10-19) — `_apply_recommended_model` жил только
в Telegram; CLI шёл через `loop.run → router.resolve → group_for_mode` и
брал kimi вместо deepseek. Один и тот же режим — разное поведение. Если бы
выбор модели был в ядре — расхождения бы не было.

### Что считается бизнес-логикой (только в ядре)

- выбор модели (роутер, recommended, model_manual);
- режимы (PLAN/ACT/AUDIT/CHAT) и их правила;
- бюджет (MAX_COST_*), watchdog, лимиты итераций;
- сжатие истории (compress), work_state, read_paths;
- tool-политика (extract, registry, approvals);
- валидация конфига (`config.validate()`).

### Что допустимо в адаптерах

- парсинг аргументов/сообщений → вызов ядра;
- рендер результата (терминал/HTML/Telegram);
- транспортные события (`LoopEvents`);
- UI-специфичное (кнопки, меню, стриминг).

### Чек-лист новой фичи

1. Логика — в ядре, с тестом в `tests/`.
2. Адаптеры только вызывают ядро; если нужен разный текст — параметр,
   не дубль логики.
3. Проверить оба пути: CLI (`agent-coder ...`) и Telegram (`/mode ...`).
   Расхождение поведения = баг.
4. `config.validate()` вызывается в обеих точках входа.
5. Промт режима — специфика режима (AUDIT: `audit_standard.md`, без
   AGENTS.md по дизайну). Это не нарушение единого ядра: логика одна,
   текст промта у режима свой.

### Известные расхождения (чинить при касании)

- **`--model` в CLI не ставит `model_manual=True`** (`__main__.py:334,339`):
  явный `--model X` перекрывается роутером (`loop.run` → recommended),
  если `MODEL_ROUTER_ENABLED=1`. В Telegram `setmodel` ставит флаг
  (`session_menu.py:95`). Один и тот же «выбор модели пользователем» —
  разное поведение. Фикс: в CLI при явном `--model` (≠ дефолт) ставить
  `model_manual=True`.

Сверено с кодом 2026-10-19: `config.validate()` вызывается в обеих
точках (`__main__.py:300`, `bot.py:111`) — расхождения нет.

## Операции с хостовым окружением

Инвентарь и инструкции по systemd, botctl и окружению хоста находятся в
`docs/ENVIRONMENT.md`. Обращайся к ним только для задач, связанных с хостом.
Не меняй host-level конфигурацию без явного запроса пользователя.
